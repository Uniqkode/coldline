01

Evidence before a decision

A finding carries a source reference and a human review action. The optional AI adapter validates text quotations against supplied evidence. Image observations still require professional or appointed operator review.

02

Access and responsibilities

Public sample access opens prepared records and stores changes in this browser. The Azure API implements Microsoft Entra identity, tenant membership, and reviewer/operator/viewer permissions. They become active only in a configured Azure deployment.

03

A deliberate data handoff

Prepared case reviews stay in the browser. The connected-analysis action sends entered text and selected images to the service address you configure, and then to its configured AI provider. Use authorized test data until the operational data agreement and access controls are established.

04

Server-side credentials

The AI adapter reads provider keys and Azure tokens from the server environment. A remote listener requires a service access token. No provider credential is embedded in the public website. The Azure deployment uses Key Vault references and managed identity for the API; the standalone test adapter uses its own server configuration.

05

Data lifecycle

Local record changes, retained reports and optional project briefs can be reset for this brand. Downloaded files and material submitted to another service have their own lifecycle. Before a real-data rollout, agree storage region, access, retention, backup and deletion responsibilities.

06

Operational controls

The adapter applies input limits, source checks, repeated-request caching and an analysis rate cap. The Azure package adds durable audit events, tenant storage, request telemetry, and optional private data endpoints. Audit retention locking, incident alert ownership, and operational verification remain deployment tasks.

Infrastructure for agriculture workloads.

DEPLOYMENT & ACTIVATION

Azure Static Web Apps

Serve the product interface through managed HTTPS and a CDN when the Azure deployment is configured. The current public release is hosted on GitHub Pages.

Implementation included where described. Azure resources must be provisioned and verified.
DEPLOYMENT & ACTIVATION

Microsoft Entra ID

Microsoft Entra sign-in, server-verified organization membership, operator/reviewer/viewer roles, and trial expiry checks are implemented. Activate them through the Azure deployment; public demo sessions grant no organization access.

Implementation included where described. Azure resources must be provisioned and verified.
DEPLOYMENT & ACTIVATION

Azure Blob Storage

The API stores each organization’s shipment records and connected reports in a separate tenant container. Conditional writes prevent lost updates. Azure encryption, versioning, and retention settings are included in the deployment template.

Implementation included where described. Azure resources must be provisioned and verified.
DEPLOYMENT & ACTIVATION

Azure Key Vault + managed identity

Functions use managed identity for tenant storage and Azure inference. Secret references point to Key Vault. Provider credentials are excluded from public browser files.

Implementation included where described. Azure resources must be provisioned and verified.
DEPLOYMENT & ACTIVATION

Azure Service Bus + Azure ML

Queue new inputs, cache unchanged evidence and handle failed jobs. Select CPU, managed inference or evaluated GPU serving according to the product’s model path.

AKS GPU serving is an alternative to evaluate if self-hosted inference is justified.
DEPLOYMENT & ACTIVATION

Azure Private Link

The deployment includes an optional VNet path with private Blob Storage and API-vault endpoints. The linked Functions ingress remains protected by Static Web Apps authentication; it must be publicly reachable by that service.

Implementation included where described. Azure resources must be provisioned and verified.
DEPLOYMENT & ACTIVATION

Azure Monitor, Application Insights + Defender for Cloud

Request metadata and measured analysis usage feed Application Insights. Audit events retain a durable retry path and a dedicated retention container. Defender plans are provided as a separate optional template; alert ownership and retention locking require deployment review.

Implementation included where described. Azure resources must be provisioned and verified.

The public release runs on GitHub Pages. Azure resource activation and observed service performance must be verified separately.
